# Frontend Test Assignment for GREEN API (Telegram UI Client)

Результат выполнения тестового задания для **GREEN API**. Задача — разработать клиентское приложение для работы с инстансом Telegram, взяв за визуальную основу интерфейс **Telegram**. 

**🔗 Ссылка на деплой (Vercel):** [frontend-test-assignment-seven.vercel.app](frontend-test-assignment-seven.vercel.app)


##  Визуальная часть и UX

Интерфейс приложения детально повторяет узнаваемую стилистику Telegram:
*   **Кастомная стилизация:** Фирменный базовый синий цвет, аккуратные облачка сообщений и адаптированные модальные окна. Фирменные обои чата взяты из открытого источника, оптимизированы для быстрой загрузки и аккуратно наложены маской.
*   **Dark Theme:** По умолчанию (и для удобства разработчика) приложение работает в темной теме.
*   **Сайдбар и модалки:** Так как отображение списка чатов не требовалось по ТЗ, левый сайдбар оставлен пустым ради узнаваемости интерфейса. В него лаконично встроена кнопка создания чата, которая открывает кастомную модалку добавления нового контакта (дизайн также списан с Telegram).
*   **Адаптивная верстка:** Интерфейс полностью отзывчив, корректно перестраивается и отлично выглядит как на десктопе, так и на экранах мобильных устройств.



## Функционал и обработка состояний

*   **Real-time сообщения:** Получение входящих сообщений реализовано в реальном времени с помощью механизма **Long Polling** (метод `ReceiveNotification`).
*   **Валидация «на лету»:** Формы ввода API-ключей на экране логина и номера телефона в модальном окне имеют встроенную проверку. Если данные некорректны — кнопка отправки блокируется (`disabled`), исключая лишние невалидные запросы к бэкенду.
*   **Статусы сообщений:** В чате обрабатываются и отображаются три состояния отправки:
    *   🕒 *Иконка часов* — сообщение в процессе отправки.
    *   🔴 *Иконка ошибки* — визуальный индикатор, если при отправке что-то пошло не так.


##  Архитектура проекта

Кодовая база структурирована по методологии **Feature-Sliced Design (FSD)**. Этот подход выбран осознанно, чтобы разделить логику приложения на изолированные куски и заложить прочный фундамент для масштабируемости проекта.

```
src/
├── app/         # Настройка приложения, глобальные стили, роутинг
├── pages/       # Экраны приложения (Login, Chat)
├── widgets/     # Крупные блоки интерфейса (Окно чата, Сайдбар)
├── features/    # Действия с бизнес-ценностью (Отправка сообщения, подписка на сообщения)
├── entities/    # Бизнес-сущности (Сообщения) и их локальные стейты
└── shared/      # Переиспользуемые UI-компоненты, API-клиент, хелперы и типы
```



##  Стек технологий

*   **React 18** + **TypeScript** (строгая типизация данных)
*   **Vite** (молниеносная сборка)
*   **Tailwind CSS** + **clsx** (быстрая верстка и удобное динамическое управление классами)
*   **SVGR** (удобная работа с иконками как с React-компонентами)
*   **React Router** (декларативный роутинг в приложении)
*   **Jotai** (микро-стейт менеджер для атомарного управления состоянием)

##  Локальный запуск

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Запустите проект в режиме разработки:
   ```bash
   npm run dev
   ```
4. Откройте `http://localhost:5173` в браузере.
